Drivers teach tmt about a terminal host or an agent program. External host drivers work today; Herdr's driver ships with tmt. The [driver protocol](https://github.com/tmt-ninja/tmt/blob/main/contracts/driver-protocol-v1.md) defines the operations and wire format.

### Two kinds

<Terms>
  <dt>host driver</dt>
  <dd>
    Finds panes, captures output, delivers input and changes focus. tmux is built in; Herdr uses an
    external executable.
  </dd>
  <dt>runtime driver</dt>
  <dd>
    Recognizes an agent, reads its hooks and plans its launch or resume. Claude Code, Codex, agy and
    Pi have built-in runtime drivers.
  </dd>
</Terms>

<Callout title="External runtime drivers are not active yet.">
  You can approve and list a runtime driver, and approval shows its declared write locations.
  Recognition, launch, hooks and setup do not yet use external runtime drivers. Approval alone does
  not replace a built-in driver.
</Callout>

### A driver is a program

An external driver is an executable. tmt calls it once per operation with a JSON request and reads one JSON answer. Implement the protocol's capabilities and the operations for your driver kind; follow its deadlines, size limits and error meanings. A send whose outcome is uncertain must not be retried automatically.

Use the [protocol crate and conformance harness](https://github.com/tmt-ninja/tmt/tree/main/rust/crates/tmt-driver-protocol) when developing a driver. The shipped [Herdr driver](https://github.com/tmt-ninja/tmt/tree/main/drivers/herdr) is an external host implementation to read alongside the contract.

### Approve and inspect

Run approval yourself in a terminal. Read the executable's declared capabilities before accepting:

<Cmd>{`
$ tmt driver install ./tmt-driver-screen
$ tmt driver ls
$ tmt driver rm screen
`}</Cmd>

A third-party driver needs explicit approval. The shipped Herdr driver is the exception: a command that works with hosts, such as `tmt ls`, approves it on first use in a Herdr pane. Removing Herdr prevents automatic reapproval until you explicitly install it again.

### Changes and removal

If an approved executable is missing or changed, tmt reports it instead of trusting the old approval. A shipped driver update can reuse approval when its declared capabilities have not expanded. Removing a host driver keeps its bindings stored, but unavailable until the driver is approved again.

### Keep state in its owner

Use the protocol's evidence and error responses rather than guessing whether a pane exists or input arrived. tmt verifies bindings and keeps identities and requests in its own storage. A driver must not open that database. Changes to agent settings belong to the user's consented setup flow.
