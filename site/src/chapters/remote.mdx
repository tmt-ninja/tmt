Remote provides a local browser door and sharing through a Firebase project you own. Start locally to read agents and use installed browser apps. For another machine, deploy Firestore, invite its owner and choose sending permissions in each direction.

### Start the local door

<Cmd>{`
$ tmt extension install remote
$ tmt remote serve
$ tmt remote status --json
`}</Cmd>

The ordinary `serve` command starts in the background and prints the local browser address. `--foreground` keeps it attached to your terminal. It listens on IPv4 loopback; this address is not a public website. Run `tmt remote stop` to stop it while keeping paired devices.

### Connect your browser

Open the running door yourself:

<Cmd>{`$ tmt remote open /remote/`}</Cmd>

A new browser connects with read-only access. For manual pairing, run `tmt remote pair`, open its link or enter its code, compare the four words and confirm. Pairing is read-only with no expiry by default. To allow sending, the owner can use `--talk`; `--agents` narrows the agent UUIDs and `--hold` requires local approval. The person who owns the machine performs pairing and permission changes.

### Connect two machines

First complete the [Firestore setup](/#review-and-deploy) on the deployment owner's machine. Keep `tmt remote serve` running on both machines. The owner invites the collaborator:

<Cmd>{`
$ tmt remote invite --remote <owned-remote>
$ tmt remote join <code>    # on the collaborator's machine
`}</Cmd>

Share the one-use code privately. Compare the four words through a trusted conversation. Each person chooses whether the other may send to their agents; both choices default to no. Keep the remote references printed by the commands.

### Send and read a reply

Use an existing local identity as the sender and the peer reference from pairing:

<Cmd>{`
$ tmt talk --identity coordinator --remote <peer-reference> reviewer "Review the patch."
$ tmt result <request-id> --json
`}</Cmd>

The remote recipient answers with its ordinary receipt-bound `tmt reply`. With both local doors running, the encrypted final returns to the originating machine. After it is stored there, you can read that result offline. An uncertain delivery is not a reason to send the same request again; keep its request ID and inspect the original result.

### Manage access

<Cmd>{`
$ tmt remote members
$ tmt remote members sending <member-id> on
`}</Cmd>

Each receiving owner controls sending, allowed agents and held requests. A held send waits for local approval; `tmt remote approve` reviews one frozen operation. Use `tmt remote members --help` to inspect machines or revoke access. Removing a remembered remote reference with `tmt remote rm` is not the same as revoking a member.

Remote does not run a central TMT service. Firestore sharing uses the project you deployed; stopping the local door postpones delivery without cancelling stored requests. Browser pairing, cloud sign-in and permission to send are separate steps.
