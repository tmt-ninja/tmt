### Start a squad

A squad is a room named `squad-<name>`. Add agents you already run, choose a lead, then open the board. Selecting a lead is separate from a member's descriptive role. Removing a member from a squad does not stop that agent.

<Cmd>{`
$ tmt extension install ops --skills
$ tmt ops squad init product
$ tmt ops squad add builder reviewer --squad product
$ tmt ops squad lead reviewer --squad product
$ tmt ops ui
`}</Cmd>

Choosing a lead also offers to publish the current Ops leads to Core's orchestration settings. Review and confirm that separate preview; declining it keeps the squad change. The board's **New member** form can start an agent through an available host after you review its command. Adding an existing member with `squad add` does not start it.

Ops uses your configured user identity for the board. `tmt ops squad me` shows it; `tmt ops squad me ben` sets the same global name as `tmt config set user.name ben --global`. This is independent of which agent leads a squad.

### The workspace

**Agents** shows a full-width Usage band above a squad/member tree and the selected conversation. Select a squad to inspect its members, or a member for **Talk**, **Measure** and **Checklist**. The Common pool contains identities with no Ops squad membership; a pool member has no squad conversation checklist. **Digest** opens a separate view of batching and usage. **Orchestration** shows Core's plans and effective policies; see [Orchestration](/working/orchestration).

The board acquires information in the background. A missing observation is unknown, not idle or zero. The shell's attention summary stays global when you switch views. Manual task/state fields, a checklist's open items and requests awaiting your reply are separate facts.

| Default key     | In the workspace                                                          |
| --------------- | ------------------------------------------------------------------------- |
| `1` / `2` / `3` | Agents / Digest / Orchestration, while an editor is not consuming the key |
| `T` / `M` / `C` | Talk / Measure / the selected member's Checklist                          |
| Enter           | Focus the selected conversation's composer                                |
| Tab / Shift+Tab | Move pane focus; an active editor or dialog handles its own keys first    |
| `e`             | Edit the selected member or squad                                         |
| `l`             | Choose a private board label for a member                                 |
| `,` / `?`       | Settings / effective help                                                 |
| Ctrl+R          | Refresh                                                                   |

Your configured bindings win. Read the footer and `?` for actions available on the selected target. A click focuses its pane without sending; scrolling a pane does not change the message recipient. The focused control rule is brighter and marked with `▸`; selection remains distinct from keyboard focus.

### Talk without losing your place

Enter sends from the composer. Alt+Enter or Ctrl+J inserts a newline; Shift+Enter also works when the terminal reports enhanced keys. Esc leaves the editor with its draft kept. Bracketed paste never submits. Drafts follow the agent's UUID across view and membership changes, but ordinary board restarts do not preserve them.

Reading older output pauses follow. **Jump to latest** or End returns to the newest messages. Correlated replies and observed pane output are labeled separately; pane text alone does not complete a request. An accepted request clears the submitted draft even if delivery is uncertain. Inspect that request before sending again. A refusal that retained no request keeps the draft.

### Checklists belong to a room

A room has its own manually authored checklist. Each member can also have a separate conversation checklist in that room. The room and member UUIDs keep these lists stable through renames; another identity with the same name does not inherit them. Reads do not create a list. The first admitted add creates it.

On a member, press **C** for Checklist. In a chat editor, **Ctrl+L** opens the selected member's checklist while preserving the draft and caret; Esc returns to the editor. Links and todos are shown together with their authors and ages when known. An item with a reference can still be open or complete; archived items are hidden from the ordinary list and its counts.

<Code>{`
Checklist · builder
[ ] Verify the final head       you · 2m
    https://example.org/review
[x] Record the build result     builder · 5m
`}</Code>

<Caption>
  Illustrative checklist states. The link is a reference, not a task dispatch. A checked item does
  not answer a request or clear the member's pending state.
</Caption>

An agent can keep its own conversation list with three short commands. When it belongs to several squads, add `--room` with the exact room UUID. Use the short item ID returned by your own `add` or `ls`, not the example ID below.

<Cmd>{`
$ tmt ops squad checklist add "Verify the final head"
$ tmt ops squad checklist ls --json
$ tmt ops squad checklist done 3f2a
`}</Cmd>

To inspect a particular room or member list, use explicit identifiers. These read-only examples use a placeholder room UUID; replace it with the room you intend to read.

<Cmd>{`
$ tmt ops squad checklist ls --room 44444444-4444-4444-8444-444444444444 --json
$ tmt ops squad checklist ls --room 44444444-4444-4444-8444-444444444444 --member builder --json
`}</Cmd>

| Who                       | Allowed checklist changes                                                      |
| ------------------------- | ------------------------------------------------------------------------------ |
| Current room member       | Create an unassigned item; edit content; complete or reopen an unarchived item |
| User or current room lead | Those actions, plus assign/unassign, archive/restore, delete and reorder       |

Even initial self-assignment requires manager permission. An assignee must be an active member of the same room. Assignment records responsibility; it does not send a message, start an agent or update task/pending fields. A member who leaves remains shown as an unavailable assignee until a manager changes it.

For automation, `create`, `edit`, `assign`, `complete` and the other explicit verbs use exact UUIDs and item/inventory revisions. `tmt ops squad checklist --help` and each verb's help describe their inputs. A stale revision or changed permission refuses the mutation: inspect the current list, review again and make a new explicit choice. **Outcome unknown** is not permission to replay. The board uses the same admission and revision checks.

Archive retains the item's content, completion and position; restore makes it visible again without changing completion. Delete removes authored content and keeps a minimal tombstone. Completing an item changes no request, inbox attention, manual state or pending flag. Answer a waiting request separately.

### Read usage as observations

Token windows show completed-request totals, not tokens per second or a forecast. Input plus output counts cached input once. Choose **Token window** in Settings. `0` is a measured zero; incomplete coverage and unavailable readings have their own marks. A member without counters is not a zero-cost member, and mixed providers' token totals are not comparable prices.

The displayed digits may ease toward a new total for at most 600 ms. That transition changes presentation only: the settled total, shares and coverage come from the observations. First readings, unavailable values, owner/window changes and reduced motion settle immediately.

Digest's **Est. ctx avoided** is an estimate of context input avoided by batching, not measured billed tokens, turns or money saved. Its range is separate from the Agents token window. Read coverage alongside any total.

### Make it yours

Use `,` for settings and the effective controls shown there. **New member** and **Edit** show the proposed commands or changes before applying them; a failure can leave some steps applied and others not run. Read that result instead of treating a closed dialog as success. User-owned settings are never changed merely by reading an example here.

<Cmd>{`
$ tmt ops ui --squad product --squad infra
$ tmt ops ui --view popup --popup
$ tmt ops ui --tab digest
$ tmt ops squad config show --squad product
`}</Cmd>

Repeat `--squad` to limit this board session without rewriting saved hidden squads. A named `--view` keeps an independent destination, selection, search and pane layout. **Reset view** clears that layer; it does not remove squad members or their work. In-place reload keeps the current view and position.

### Layout: rows, lines and panes

The interactive Agents tree and conversation have their own layout. Drag a visible divider to resize adjacent panes; double-click it to restore the default. Small terminals retain usable minimum sizes and may show one focused pane. Pane ratios belong to the named view.

Custom rows, columns, sections and `[tabs.<name>]` configurations still describe the independent command-line member projection. They do not add interactive shell tabs or rearrange the Agents tree. Read one with `tmt ops squad ls --tab <name> --json`. The [Ops skill](https://github.com/tmt-ninja/tmt/blob/main/extensions/tmt-ops/skills/tmt-ops/SKILL.md) owns the detailed configuration reference.

### Colors and themes

The board theme is separate from command-line colors. Choose **Theme** in Settings; scope it to all boards or the selected squad. Words, symbols and focus cues carry the meaning even with `NO_COLOR`; color alone never establishes working, blocked or waiting state. Basic drivers cannot report the same activity/model detail as full drivers, and the board labels that limitation.

### Jumping between members

Talking in the board and jumping to the agent's terminal are different actions. Use the selected member's available jump action, or the commands below in your tmux client. Jumping changes your view, not the recipient's work; return goes back to where that squad jump started.

<Cmd>{`
$ tmt ops squad jump builder --squad product
$ tmt ops squad back
`}</Cmd>

The board can also show a member's Session information. Read its exact target and proposed resume/move command before confirming. Missing or unobserved runtime state is not evidence that starting another agent is safe.

### Skills for your lead

`tmt extension install ops --skills` publishes the lead skill with the extension. Ask the lead to read it and agree on naming, dispatch, status updates and review conventions. The skill describes what commands do; it does not grant permission to launch extra agents or change your workflow.

### Where state lives

Core owns identities, room membership, requests and replies. Ops owns its checklists and board preferences; the view cache is disposable. A member's notebook comes from `tmt notes path`, not a second copy in a row's `note` field. Keep durable working context there and use task, state and pending fields for the current summary.
