### Start a squad

A squad is a room named `squad-<name>`. Add agents you already run, choose a lead, then open the board. Selecting a lead is separate from a member's descriptive role. Removing a member from a squad does not stop that agent.

<Cmd>{`
$ tmt extension install ops --skills
$ tmt ops squad init product
$ tmt ops squad add builder reviewer --squad product
$ tmt ops squad lead reviewer --squad product
$ tmt ops ui
`}</Cmd>

Choosing a lead also offers to publish the current Ops leads to Core's orchestration settings. Review and confirm that separate preview; declining it keeps the squad change. The board's **New member** form can start an agent through an available host after you review its command. Adding an existing member with `squad add` does not start it.

Ops uses your configured user identity for the board. `tmt ops squad me` shows it; `tmt ops squad me ben` sets the same global name as `tmt config set user.name ben --global`. This is independent of which agent leads a squad.

### The workspace

**Agents** shows a full-width Usage band above a squad/member tree and the selected conversation. Select a squad to inspect its members, or a member for **Talk**, **Measure** and **Checklist**. The Common pool contains identities with no Ops squad membership; a pool member has no squad conversation checklist. **Work** shows Colab's work list. **Digest** opens a separate view of batching and usage. **Orchestration** shows Core's plans and effective policies; see [Orchestration](/working/orchestration).

<Code>{`
OPS / UI · Agents
Usage: observed totals and provider limits
Squads / members       │ Talk · Measure · Checklist
▾ product              │ builder
  reviewer             │ Request and reply history
  builder              │
Common pool            │ Message to builder
`}</Code>

The board refreshes information in the background. Missing readings mean unknown, not idle or zero. The attention summary stays visible across views.

| Default key           | In the workspace                                                                 |
| --------------------- | -------------------------------------------------------------------------------- |
| `1` / `2` / `3` / `4` | Agents / Work / Digest / Orchestration, while an editor is not consuming the key |
| `T` / `M` / `C`       | Talk / Measure / the selected member's Checklist                                 |
| Enter                 | Focus the selected conversation's composer                                       |
| Tab / Shift+Tab       | Move pane focus; an active editor or dialog handles its own keys first           |
| `r`                   | Rename the selected member or squad                                              |
| `l`                   | Choose a private board label for a member                                        |
| `,` / `?`             | Settings / effective help                                                        |
| Ctrl+R                | Refresh                                                                          |

Read the footer and `?` for the keys available on the selected target. Your configured bindings take precedence. Click a pane to focus it; the focused control is marked with `▸`.

### Colab work on the board

In **Work**, press `p` to select a project, `d` to choose the Done period and `c` to show recent completions. Enter opens the selected page when its link is available. In a selected project, `m` lets you move eligible numbered work after confirmation. If the order changed elsewhere, the board shows the current order without retrying your move. Work requires Colab 0.1.0-alpha.478 or later; ordering requires alpha.481 or later.

Press `t` on a work item whose owner resolves to a squad member to open Talk over Work. Esc returns to Work; Tab opens the full conversation.

### Talk without losing your place

Enter sends from the composer. Alt+Enter or Ctrl+J inserts a newline; Shift+Enter also works when the terminal reports enhanced keys. Esc leaves the editor with its draft kept. You can switch views without losing a draft, but restarting the board clears it.

Reading older output pauses follow. **Jump to latest** or End returns to the newest messages. Replies and pane output are labeled separately. If delivery is uncertain, inspect the request before sending again.

Submit `!command` in Talk to run a shell command in that member's verified directory. `!!` is an alias. Output appears live in **Run command** and is never attached to the next message. A command's **Run…** action in the transcript opens the same window with the command filled in; review the target before running it.

When a member has a waiting provider form, **◆ form** marks it. Press `f` or choose **Answer form** to answer a complete form that Core supports. Only people answer these forms. Truncated, stale or terminal-only forms stay read-only; use the member's terminal for terminal-only answers. Check an unconfirmed send there before doing anything else; Ops never resends it.

### Checklists belong to a room

Each room has a checklist, and each member can have a separate conversation checklist within it. Lists stay with the room and member when you rename them.

Select a member and press **C** for Checklist. In a chat editor, **Ctrl+L** opens that list while keeping your draft and caret; Esc returns to the editor. Links and todos appear with their authors and ages. Archived items are hidden.

Type `#` in Talk to search Colab Work numbers and titles alongside that member's Checklist. Enter inserts a work number such as `#TUI-12`; the agent receives its number and title. Select a known work number in the conversation and press Enter to open it in Colab or copy it. Checklist references still offer **Open in checklist**, and `r` in Checklist quotes the selected item into Talk.

<Code>{`
Checklist · builder
[ ] Verify the final head       you · 2m
    https://example.org/review
[x] Record the build result     builder · 5m
`}</Code>

<Caption>
  Example checklist. Checking an item completes the todo; answer any waiting request separately.
</Caption>

An agent can keep its own conversation list with three short commands. When it belongs to several squads, add `--room` with the exact room UUID. Use the short item ID returned by your own `add` or `ls`, not the example ID below.

<Cmd>{`
$ tmt ops squad checklist add "Verify the final head"
$ tmt ops squad checklist ls --json
$ tmt ops squad checklist done 3f2a
`}</Cmd>

To inspect a particular room or member list, use explicit identifiers. These read-only examples use a placeholder room UUID; replace it with the room you intend to read.

<Cmd>{`
$ tmt ops squad checklist ls --room 44444444-4444-4444-8444-444444444444 --json
$ tmt ops squad checklist ls --room 44444444-4444-4444-8444-444444444444 --member builder --json
`}</Cmd>

| Who                       | Allowed checklist changes                                                      |
| ------------------------- | ------------------------------------------------------------------------------ |
| Current room member       | Create an unassigned item; edit content; complete or reopen an unarchived item |
| User or current room lead | Those actions, plus assign/unassign, archive/restore, delete and reorder       |

For more checklist actions, run `tmt ops squad checklist --help`.

### Read usage as observations

The Agents tree has one **TOK** column. Its **Range** cycles through 5m, 10m, 1h, 3h, 6h, 1d and 7d; **TOK range** in Settings selects the same interval. A recent observed increase makes the figure bold. Input plus output counts cached input once. Missing readings are not zero, and token totals are not prices. Click the **TOK** heading or a figure to switch between tokens and an uncached-input list-price estimate, not a bill.

Digest's **Est. ctx avoided** is an estimate of context input avoided by batching, not measured billed tokens, turns or money saved. Its range is separate from the Agents token window. Read coverage alongside any total.

The Digest **Saved** detail also shows settled message and batch counts for its selected range. Partial or stale coverage is marked alongside those counts.

Digest's browser page adds allowance runway, **Usage share** by model and seat, and usage trends. Runway projects recent readings toward the reset; it is not a guarantee. API-equivalent costs use dated list prices for uncached input, cache reads, cache writes and output. Missing prices stay unavailable and incomplete estimates are labeled as lower bounds. These figures are separate from subscription allowance and your bill. `tmt digest usage report --since 7d --json` reads the report from the command line.

### Make it yours

Press `,` for Settings. **New member** and **Edit** let you review the proposed commands or changes before applying them.

<Cmd>{`
$ tmt ops ui --squad product --squad infra
$ tmt ops ui --view popup --popup
$ tmt ops ui --tab digest
$ tmt ops squad config show --squad product
`}</Cmd>

Repeat `--squad` to limit this board session without rewriting saved hidden squads. A named `--view` keeps an independent destination, selection, search and pane layout. **Reset view** clears that layer; it does not remove squad members or their work. In-place reload keeps the current view and position.

### Layout: rows, lines and panes

The interactive Agents tree and conversation have their own layout. Drag a visible divider to resize adjacent panes; double-click it to restore the default. Small terminals retain usable minimum sizes and may show one focused pane. Pane ratios belong to the named view.

Custom rows, columns, sections and `[tabs.<name>]` configurations still describe the independent command-line member projection. They do not add interactive shell tabs or rearrange the Agents tree. Read one with `tmt ops squad ls --tab <name> --json`. The [Ops skill](https://github.com/tmt-ninja/tmt/blob/main/extensions/tmt-ops/skills/tmt-ops/SKILL.md) owns the detailed configuration reference.

### Colors and themes

The board theme is separate from command-line colors. Choose **Theme** in Settings; scope it to all boards or the selected squad. Words, symbols and focus cues carry the meaning even with `NO_COLOR`; color alone never establishes working, blocked or waiting state. Basic drivers cannot report the same activity/model detail as full drivers, and the board labels that limitation.

### Jumping between members

Talking in the board and jumping to the agent's terminal are different actions. Use the selected member's available jump action, or the commands below in your tmux client. Jumping changes your view, not the recipient's work; return goes back to where that squad jump started.

<Cmd>{`
$ tmt ops squad jump builder --squad product
$ tmt ops squad back
`}</Cmd>

Open a member's Session information to review its target and proposed resume or move command.

### Skills for your lead

`tmt extension install ops --skills` publishes the lead skill with the extension. Ask the lead to read it and agree on naming, dispatch, status updates and review conventions.

### Where state lives

Use `tmt notes path` to find a member's notebook and keep durable working context there. Set the member's `state` on the board, record progress on the issue, and use a request or Colab question when you need an answer from the user.
