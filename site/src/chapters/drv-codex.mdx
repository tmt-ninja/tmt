### Connect it

<Cmd>{`
$ tmt setup codex           # shows the exact config change, then asks
$ tmt run builder codex     # start Codex as "builder"
$ tmt resume builder        # reopen builder's own thread
`}</Cmd>

Setup adds Codex's lifecycle hooks for tmt. Codex asks you to trust new hooks the first time; that's expected. `tmt setup codex --remove` takes them out again.

### Message delivery

`tmt run <name> codex` and `tmt resume <name>` use plain paste delivery by default. Pass `--channel` to opt into Codex's native message channel. With the channel, `talk` queues input through a private app-server without pasting into the pane or interrupting your typing. Each channel session has one extra owned app-server process and a supervisor; tmt cleans them up when its foreground exits, including Ctrl-C.

The [run and resume options](/working#tmt-run) let you choose plain paste delivery or require a channel.

<Cmd>{`
$ tmt run --channel builder codex    # opt into the channel
$ tmt resume --channel builder       # require the channel for this exact thread
`}</Cmd>

If tmt has not tested your Codex version or cannot set up the requested channel safely before startup, `--channel` fails. If the pane may already be attached to a channel, tmt refuses to fall back to paste. Once enrolled, a channel that is not ready or cannot deliver stays an error; tmt never pastes into that pane instead.

Codex may ask you to trust the launch folder. Answer that prompt yourself in its TUI. tmt never answers it or changes trust settings, and input already accepted into the queue may wait until you complete attachment. Running plain `codex` is unchanged; tmt changes no global Codex configuration, authentication or hooks for channel enrollment.

### Codex's sandbox

A plain Codex workspace-write session may not have access to tmt's data directory. tmt reports a denied write as `STORAGE_NOT_WRITABLE` with the directory's path. `tmt run <name> codex` supplies launch-scoped access to that directory without editing global Codex settings. For an already running session, use Codex's own permission flow to allow the directory or escalate the command; an agent should not change your settings without your OK.

### Usage counters

On a new installation, `tmt setup codex` enables collection of Codex's context size and completed-request tokens by default. `--no-usage` disables collection and remembers that choice; `--usage` enables it. The turn-end hook records the values; [Usage counters](/drivers#usage-counters) lists the fields. Codex states its context window, so `windowTokens` is filled in. Codex's counters follow the provider's own running totals: the first reading is the starting point, and later turns add to it.
