<Lede>
  Squad 讓 lead 與成員在同一處協調工作。Ops 顯示對話、工作與清單；由 lead 決定誰負責什麼。
</Lede>

<Mdx.h3 id="start-a-squad">建立 squad</Mdx.h3>

Squad 是名稱為 `squad-<name>` 的 room。加入已經在執行的 agent、選擇 lead，再開啟 board。指定 lead 與成員的描述性 role 是兩回事。從 squad 移除成員不會停止該 agent。

<Cmd>{`
$ tmt extension install ops --skills
$ tmt ops squad init product
$ tmt ops squad add builder reviewer --squad product
$ tmt ops squad lead reviewer --squad product
$ tmt ops ui
`}</Cmd>

選擇 lead 時，也會提供將目前 Ops leads 發布到 Core orchestration 設定的選項。請另外檢閱並確認該預覽；拒絕發布不會撤銷 squad 的變更。board 的 **New member** 表單可在你檢閱命令後，透過可用的 host 啟動 agent。使用 `squad add` 加入既有成員不會啟動它。

Ops board 使用你設定的使用者身分。`tmt ops squad me` 顯示該身分；`tmt ops squad me ben` 設定的全域名稱與 `tmt config set user.name ben --global` 相同。這與哪個 agent 擔任 squad lead 無關。

<Mdx.h3 id="the-workspace">工作區</Mdx.h3>

**Agents** 在 squad／成員樹狀清單與所選對話上方，顯示橫跨整個寬度的 Usage 區域。選擇 squad 可查看成員；選擇成員可查看 **Talk**、**Measure** 與 **Checklist**。Common pool 收錄未加入任何 Ops squad 的身分；其中的成員沒有 squad 對話清單。**Work** 顯示 Colab 的工作清單。**Digest** 另外顯示訊息批次處理與用量。**Orchestration** 顯示 Core 的計畫及生效政策；請見 [Orchestration](/working/orchestration)。

<Code>{`
OPS / UI · Agents
Usage: observed totals and provider limits
Squads / members       │ Talk · Measure · Checklist
▾ product              │ builder
  reviewer             │ Request and reply history
  builder              │
Common pool            │ Message to builder
`}</Code>

<Caption>Agents 視圖示意圖。寬終端機會並排顯示，較窄時會上下堆疊或只顯示聚焦窗格。</Caption>

board 在背景更新資訊。缺少讀數表示未知，不代表閒置或零。切換視圖時，注意事項摘要仍會顯示。

| 預設按鍵              | 工作區中的動作                                                 |
| --------------------- | -------------------------------------------------------------- |
| `1` / `2` / `3` / `4` | Agents / Work / Digest / Orchestration；編輯器未攔截按鍵時生效 |
| `T` / `M` / `C`       | Talk / Measure / 所選成員的 Checklist                          |
| Enter                 | 聚焦所選對話的輸入框                                           |
| Tab / Shift+Tab       | 移動窗格焦點；啟用中的編輯器或對話框會優先處理自己的按鍵       |
| `r`                   | 重新命名所選成員或 squad                                       |
| `l`                   | 為成員選擇私人 board 標籤                                      |
| `,` / `?`             | 設定 / 目前生效的操作說明                                      |
| Ctrl+R                | 重新整理                                                       |

查看頁尾與 `?`，了解所選目標可用的按鍵。你設定的按鍵綁定優先。點擊窗格可聚焦；目前操作的控制項標有 `▸`。

<Mdx.h3 id="colab-work-on-the-board">在 board 查看 Colab 工作</Mdx.h3>

在 **Work** 中，按 `p` 選擇專案、`d` 選擇 Done 的時間範圍、`c` 顯示最近完成的工作。有連結時，Enter 會開啟所選頁面。在選定專案中，`m` 可移動符合條件的編號工作，確認後才會執行。若其他地方已變更順序，board 會顯示目前順序，不會重試移動。Work 需要 Colab 0.1.0-alpha.478 或更新版本；排序需要 alpha.481 或更新版本。

<Mdx.h3 id="talk-without-losing-your-place">對話不中斷工作位置</Mdx.h3>

在輸入框按 Enter 送出訊息。Alt+Enter 或 Ctrl+J 插入換行；終端機支援增強按鍵回報時，也可用 Shift+Enter。Esc 離開編輯器並保留草稿。切換視圖不會遺失草稿，但重新啟動 board 會清除草稿。

閱讀較早的輸出會暫停自動跟隨。**Jump to latest** 或 End 可回到最新訊息。回覆與窗格輸出會分開標示。若送達狀態不確定，請先檢查請求再決定是否重送。

成員有待回答的 provider 表單時，會顯示 **◆ form**。按 `f` 或選擇 **Answer form**，可回答 Core 支援的完整表單。只有人可以回答這些表單。遭截斷、過時或只能在終端機回答的表單保持唯讀；終端機專用表單請到成員的終端機回答。送出未獲確認時，請先在該終端機檢查；Ops 不會重送。

<Mdx.h3 id="checklists-belong-to-a-room">清單屬於 room</Mdx.h3>

每個 room 都有清單，每位成員也可以在其中擁有獨立的對話清單。重新命名後，清單仍屬於原來的 room 與成員。

選擇成員並按 **C** 開啟 Checklist。在聊天編輯器中，**Ctrl+L** 開啟該清單並保留草稿與游標位置；Esc 返回編輯器。連結與待辦項目會顯示作者及經過時間。已封存的項目會隱藏。

在 Talk 輸入 `#` 可從該成員的 Checklist 選擇項目，按 Enter 或 Tab 插入參照。在 Checklist 按 `r` 可將所選項目引用到 Talk。對話中可解析的參照會提供 **Open in checklist**。

<Code>{`
Checklist · builder
[ ] Verify the final head       you · 2m
    https://example.org/review
[x] Record the build result     builder · 5m
`}</Code>

<Caption>清單範例。勾選項目會完成該待辦事項；等待回覆的請求仍須另外答覆。</Caption>

Agent 可用三個簡短命令維護自己的對話清單。同時加入多個 squad 時，請加上 `--room` 並指定精確的 room UUID。請使用自己執行 `add` 或 `ls` 得到的短項目 ID，不要使用下方的範例 ID。

<Cmd>{`
$ tmt ops squad checklist add "Verify the final head"
$ tmt ops squad checklist ls --json
$ tmt ops squad checklist done 3f2a
`}</Cmd>

若要查看特定 room 或成員的清單，請明確指定識別碼。以下唯讀範例使用佔位用的 room UUID；請換成你打算讀取的 room。

<Cmd>{`
$ tmt ops squad checklist ls --room 44444444-4444-4444-8444-444444444444 --json
$ tmt ops squad checklist ls --room 44444444-4444-4444-8444-444444444444 --member builder --json
`}</Cmd>

| 身分                     | 允許的清單變更                                           |
| ------------------------ | -------------------------------------------------------- |
| 目前的 room 成員         | 建立未指派項目；編輯內容；完成或重新開啟未封存的項目     |
| 使用者或目前的 room lead | 上述動作，加上指派／取消指派、封存／還原、刪除與重新排序 |

更多清單操作請執行 `tmt ops squad checklist --help` 查看。

<Mdx.h3 id="read-usage-as-observations">把用量視為觀測結果</Mdx.h3>

Agents 樹狀清單只有一個 **TOK** 欄位。**Range** 依序切換 5m、10m、1h、3h、6h、1d、7d；Settings 中的 **TOK range** 也可選擇同樣的時間範圍。近期觀測到增加時，數值會以粗體顯示。輸入加輸出只會把快取輸入計算一次。缺少讀數不代表零，token 總量也不等於費用。點擊 **TOK** 欄位標題或數值，可在 token 數與按未快取輸入牌價計算的估計費用之間切換；估計費用不是帳單。

Digest 的 **Est. ctx avoided** 是透過批次處理省下多少上下文輸入的估計，不是實測的計費 token、輪次或金額節省。它的範圍與 Agents 的 token 時間範圍獨立。讀取任何總量時，都要一起看涵蓋範圍。

Digest 的 **Saved** 詳細資訊也會顯示所選時間範圍內已結算的訊息數與批次數。涵蓋不完整或資料過時會在旁邊標明。

<Mdx.h3 id="make-it-yours">依你的方式設定</Mdx.h3>

按 `,` 開啟 Settings。**New member** 與 **Edit** 讓你在套用前檢閱預計執行的命令或變更。

<Cmd>{`
$ tmt ops ui --squad product --squad infra
$ tmt ops ui --view popup --popup
$ tmt ops ui --tab digest
$ tmt ops squad config show --squad product
`}</Cmd>

重複指定 `--squad` 可限制這次 board 工作階段的範圍，不會改寫已儲存的隱藏 squad 設定。具名的 `--view` 各自保留目的地、選取、搜尋與窗格配置。**Reset view** 清除此視圖層，不會移除 squad 成員或其工作。原地重新載入會保留目前視圖與位置。

<Mdx.h3 id="layout-rows-lines-and-panes">配置：列、顯示行與窗格</Mdx.h3>

互動式 Agents 樹狀清單與對話有自己的配置。拖曳可見分隔線可調整相鄰窗格大小；按兩下可還原預設值。小型終端機會維持可用的最小尺寸，也可能只顯示聚焦窗格。窗格比例屬於具名視圖。

自訂 rows、columns、sections 與 `[tabs.<name>]` 設定仍用於獨立的命令列成員視圖。它們不會新增互動式 shell 分頁，也不會重新排列 Agents 樹狀清單。可用 `tmt ops squad ls --tab <name> --json` 讀取。[Ops skill](https://github.com/tmt-ninja/tmt/blob/main/extensions/tmt-ops/skills/tmt-ops/SKILL.md) 提供詳細設定參考。

<Mdx.h3 id="colors-and-themes">顏色與主題</Mdx.h3>

board 主題與命令列顏色分開設定。在 Settings 選擇 **Theme**，套用至所有 board 或所選 squad。即使使用 `NO_COLOR`，文字、符號與焦點提示仍會傳達含義；顏色本身不能證明工作中、受阻或等待狀態。Basic driver 無法回報與 full driver 相同的活動／模型細節，board 會標示這項限制。

<Mdx.h3 id="jumping-between-members">切換到成員</Mdx.h3>

在 board 對話與跳到 agent 終端機是不同動作。請使用所選成員可用的跳轉動作，或在你的 tmux client 執行下列命令。跳轉會改變你看到的畫面，不會改變收件者的工作；返回則回到該次 squad 跳轉的起點。

<Cmd>{`
$ tmt ops squad jump builder --squad product
$ tmt ops squad back
`}</Cmd>

開啟成員的 Session 資訊，查看目標及預計執行的 resume 或 move 命令。

<Mdx.h3 id="skills-for-your-lead">給 lead 的 skill</Mdx.h3>

`tmt extension install ops --skills` 會隨擴充套件發布 lead skill。請 lead 閱讀它，並與你約定命名、派工、狀態更新與審查方式。

<Mdx.h3 id="where-state-lives">狀態存放在哪裡</Mdx.h3>

使用 `tmt notes path` 尋找成員的筆記本，並將持續需要的工作脈絡保留在其中。在 board 設定成員的 `state`，在 issue 記錄進度；需要使用者回答時，使用請求或 Colab 問題。
