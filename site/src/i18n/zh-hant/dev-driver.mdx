driver 教 tmt 如何操作終端機 host 或 agent 程式。外部 host driver 已可使用；Herdr 的 driver 隨 tmt 提供。[driver 協定](https://github.com/tmt-ninja/tmt/blob/main/contracts/driver-protocol-v1.md)定義了操作與通訊格式。

<Mdx.h3 id="two-kinds">兩種 driver</Mdx.h3>

<Terms>
  <dt>host driver</dt>
  <dd>尋找窗格、擷取輸出、傳遞輸入與切換焦點。tmux 已內建；Herdr 使用外部執行檔。</dd>
  <dt>runtime driver</dt>
  <dd>
    辨識 agent、讀取其 hook，並規劃啟動或恢復。Claude Code、Codex、agy 和 Pi 都有內建 runtime
    driver。 Cursor Agent 支援基本偵測與呼叫端識別，但沒有 lifecycle hook 或精確恢復對話功能。
  </dd>
</Terms>

<Callout title="外部 runtime driver 尚未參與執行。">
  你可以核准並列出 runtime driver；核准時會顯示它宣告的寫入位置。辨識、啟動、hook 和 setup
  尚未使用外部 runtime driver。僅核准它不會取代內建 driver。
</Callout>

<Mdx.h3 id="a-driver-is-a-program">driver 是一個程式</Mdx.h3>

外部 driver 是執行檔。tmt 為每項操作呼叫它一次，傳入一個 JSON 請求，再讀取一個 JSON 回答。請實作協定中對應 driver 類型的能力與操作，遵守時限、大小限制與錯誤含義。結果不確定的傳送不得自動重試。

開發 driver 時可使用[協定 crate 與一致性測試工具](https://github.com/tmt-ninja/tmt/tree/main/rust/crates/tmt-driver-protocol)。隨附的 [Herdr driver](https://github.com/tmt-ninja/tmt/tree/main/drivers/herdr)是外部 host 的實作，可對照契約閱讀。

<Mdx.h3 id="approve-and-inspect">核准與檢查</Mdx.h3>

請親自在終端機中核准。接受之前，先閱讀執行檔宣告的能力：

<Cmd>{`
$ tmt driver install ./tmt-driver-screen
$ tmt driver ls
$ tmt driver rm screen
`}</Cmd>

第三方 driver 需要明確核准。隨附的 Herdr driver 是例外：在 Herdr 窗格中首次執行 `tmt ls` 等操作 host 的命令時會自動核准。移除 Herdr 後，必須明確重新安裝，才會再次獲准使用。

<Mdx.h3 id="changes-and-removal">變更與移除</Mdx.h3>

已核准的執行檔遺失或發生變化時，tmt 會回報問題，而不會繼續信任舊核准。隨附 driver 更新時，只要宣告的能力沒有擴大，就可沿用核准。移除 host driver 會保留其 binding，但再次核准 driver 之前無法使用。

<Mdx.h3 id="keep-state-in-its-owner">由負責的元件保存狀態</Mdx.h3>

請使用協定的證據與錯誤回應，不要猜測窗格是否存在或輸入是否已送達。tmt 負責驗證 binding，並在自己的儲存空間中保存 identity 與請求。driver 不得開啟該資料庫。agent 設定的變更應由使用者已同意的 setup 流程處理。
