<Mdx.h3 id="connect-it">接上 tmt</Mdx.h3>

<Cmd>{`
$ tmt setup codex           # shows the exact config change, then asks
$ tmt run builder codex     # start Codex as "builder"
$ tmt resume builder        # reopen builder's own thread
`}</Cmd>

Setup 會為 tmt 加入 Codex 的生命週期 hook。Codex 第一次會詢問你是否信任新的 hook，這是正常的。`tmt setup codex --remove` 會移除它們。

<Mdx.h3 id="message-delivery">訊息傳送</Mdx.h3>

`tmt run <name> codex` 和 `tmt resume <name>` 預設用一般的貼上方式傳送訊息。加上 `--channel` 才會使用 Codex 原生的訊息通道。使用通道時，`talk` 會透過私有 app-server 將輸入排入佇列，不會貼進窗格，也不會打斷你的輸入。每個通道 session 都會多啟動一個由 tmt 管理的 app-server 行程與一個 supervisor；前景程式結束時，包括按下 Ctrl-C，tmt 都會清理它們。

[啟動與恢復的選項](/working#tmt-run)讓你選擇一般貼上傳送，或要求使用通道。

<Cmd>{`
$ tmt run --channel builder codex    # opt into the channel
$ tmt resume --channel builder       # require the channel for this exact thread
`}</Cmd>

如果 tmt 尚未測試你的 Codex 版本，或無法在啟動前安全地建立指定通道，`--channel` 就會失敗。如果窗格可能已經接上通道，tmt 不會改用貼上方式。加入通道後，通道尚未就緒或無法傳送都會回報錯誤；tmt 不會改把訊息貼進該窗格。

Codex 可能會詢問你是否信任啟動時的資料夾。請自己在它的 TUI 回答。tmt 不會代答或變更信任設定；已被佇列接受的輸入，可能會等你完成連接才送出。直接執行 `codex` 的方式不變；為了加入通道，tmt 不會變更任何全域 Codex 設定、認證或 hook。

<Mdx.h3 id="codex-s-sandbox">Codex 的沙盒</Mdx.h3>

一般的 Codex workspace-write session 可能無法存取 tmt 資料目錄。寫入遭拒時，tmt 會回傳 `STORAGE_NOT_WRITABLE` 與目錄路徑。`tmt run <name> codex` 會為該次啟動加入目錄存取權，不會編輯全域 Codex 設定。對於已執行的 session，請透過 Codex 自己的權限流程允許目錄或提升命令權限；agent 不應未經你同意就變更設定。

<Mdx.h3 id="usage-counters">用量計數</Mdx.h3>

新安裝時，`tmt setup codex` 預設啟用 Codex 的 context 大小與已完成請求 token 收集。`--no-usage` 關閉收集並記住選擇；`--usage` 啟用收集。每輪結束 hook 會記錄這些值；欄位請看[用量計數](/drivers#usage-counters)。Codex 會回報 context window，所以 `windowTokens` 會有值。Codex 的計數沿用 provider 自己持續累加的總量：第一次讀取作為起點，之後的輪次再加上去。
