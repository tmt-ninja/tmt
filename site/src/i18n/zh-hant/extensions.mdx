PATH 上任何名為 `tmt-<name>` 的程式，都能用 `tmt <name>` 執行，就像 gcloud 的元件會新增指令一樣。內建指令一律優先，所以擴充套件不能取代 `talk` 或 `run`。擴充套件透過 tmt 的指令、JSON 輸出與 hook 使用 tmt，和其他程式走的是同一個入口。

<Cmd>{`
$ tmt ops ui           # runs tmt-ops ui
$ tmt help             # lists extensions it found
$ tmt ops sq <Tab>     # completion comes from the extension
`}</Cmd>

<Mdx.h3 id="install-update-and-remove">安裝、更新與移除</Mdx.h3>

下面的擴充套件都用同一種方式安裝。每個都有自己的版本，各自更新。移除時會刪除指令與 skill，保留資料。

<Cmd>{`
$ tmt extension install ops       # asks before changing anything
$ tmt extension ls                # what's installed and its version; --check looks for updates
$ tmt upgrade                     # CLI, skills and installed official extensions
$ tmt extension upgrade ops       # just Ops
$ tmt extension rm ops            # your data stays
`}</Cmd>

`tmt upgrade` 也會更新你已安裝的官方擴充套件，各自沿用自己的 channel 與釘選版本，並一次詢問你是否全部更新；`--yes` 會跳過詢問。它也會提供尚未安裝的官方擴充套件；其中一個失敗，也不會撤銷其他套件的更新。[查看升級計畫 →](/working/settings#update-tmt) `tmt extension upgrade <name> --unpin` 會解除版本釘選。

一般安裝不會發布給 agent 的 skill。加上 `--skills`，會將附帶的 skill 納入你批准的安裝；不會再另外詢問是否加入 skill。要自行開發，請看[建立擴充套件](/develop/extensions)。PATH 上任何 `tmt-<name>` 都能運作，不必透過 `tmt extension`。

<Mdx.h3 id="a-command-whose-extension-is-missing">命令所需的擴充套件尚未安裝</Mdx.h3>

在人操作的終端機中執行 `tmt ops ui` 等缺少的官方命令時，tmt 會說明哪個擴充套件提供該命令，並詢問 **Install it now [Y/n]**。這項安裝包含附帶 skill。接受後會安裝，再於 **Run it again:** 後顯示原命令，不會替你執行它。拒絕不會變更任何內容。help 請求、JSON、管線與 agent 呼叫不會提供互動式安裝，而是回傳擴充套件未安裝的錯誤與明確的安裝命令。
