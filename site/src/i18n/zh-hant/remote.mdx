Remote 提供本機瀏覽器入口，並透過你自己的 Firebase 專案共享。先在本機讀取 agent、使用已安裝的瀏覽器應用程式。要連接另一台機器，請部署 Firestore、邀請其擁有者，並分別選擇兩個方向的傳送權限。

<Mdx.h3 id="start-the-local-door">啟動本機入口</Mdx.h3>

<Cmd>{`
$ tmt extension install remote
$ tmt remote serve
$ tmt remote status --json
`}</Cmd>

一般的 `serve` 命令在背景啟動，並顯示本機瀏覽器網址。`--foreground` 讓它保持連接到目前的終端機。它監聽 IPv4 回送位址，不是公開網站。執行 `tmt remote stop` 可停止服務並保留已配對的裝置。

<Mdx.h3 id="connect-your-browser">連接瀏覽器</Mdx.h3>

請親自開啟正在執行的入口：

<Cmd>{`$ tmt remote open /remote/`}</Cmd>

新瀏覽器以唯讀權限連接。手動配對時，執行 `tmt remote pair`，開啟連結或輸入代碼，對照四個單字後確認。配對預設唯讀、無到期時間。擁有者可用 `--talk` 允許傳送；`--agents` 限定 agent UUID，`--hold` 要求本機核准。配對與權限變更由機器擁有者操作。

<Mdx.h3 id="connect-two-machines">連接兩台機器</Mdx.h3>

先在部署擁有者的機器上完成 [Firestore 設定](/#review-and-deploy)。兩台機器都保持執行 `tmt remote serve`。擁有者邀請協作者：

<Cmd>{`
$ tmt remote invite --remote <owned-remote>
$ tmt remote join <code>    # on the collaborator's machine
`}</Cmd>

請私下分享一次性代碼，並透過可信的對話管道核對四個單字。雙方分別決定是否允許對方向自己的 agent 傳送訊息；兩個選項預設都不允許。請保留命令顯示的 remote 參照。

<Mdx.h3 id="send-and-read-a-reply">傳送並讀取回覆</Mdx.h3>

使用既有的本機 identity 作為傳送者，並使用配對取得的對端參照：

<Cmd>{`
$ tmt talk --identity coordinator --remote <peer-reference> reviewer "Review the patch."
$ tmt result <request-id> --json
`}</Cmd>

遠端接收者照常用綁定 receipt 的 `tmt reply` 回答。當兩端的本機入口都在執行時，加密的最終回覆會返回發起機器。回覆保存到該機器後，就能離線讀取。送達結果不確定時，不要重複傳送同一請求；保留請求 ID 並檢查原請求的結果。

<Mdx.h3 id="manage-access">管理存取</Mdx.h3>

<Cmd>{`
$ tmt remote members
$ tmt remote members sending <member-id> on
`}</Cmd>

每個接收方的擁有者負責控制傳送權限、允許的 agent 與待核准請求。待核准的傳送會等待本機核准；`tmt remote approve` 用來審閱一項內容已固定的操作。查看機器或撤銷存取的方式請見 `tmt remote members --help`。用 `tmt remote rm` 移除記住的 remote 參照，不等於撤銷成員權限。

Remote 不營運中央 TMT 服務。Firestore 共享使用你部署的專案；停止本機入口只會延後送達，不會取消已保存的請求。瀏覽器配對、雲端登入與傳送權限是不同的步驟。
