<Lede>
  Squad 让 lead 与成员在同一处协调工作。Ops 显示对话、工作与清单；由 lead 决定谁负责什么。
</Lede>

<Mdx.h3 id="start-a-squad">创建 squad</Mdx.h3>

Squad 是名称为 `squad-<name>` 的 room。加入已经在运行的 agent、选择 lead，再打开看板。指定 lead 与成员的描述性 role 是两回事。从 squad 移除成员不会停止该 agent。

<Cmd>{`
$ tmt extension install ops --skills
$ tmt ops squad init product
$ tmt ops squad add builder reviewer --squad product
$ tmt ops squad lead reviewer --squad product
$ tmt ops ui
`}</Cmd>

选择 lead 时，也会提供将当前 Ops leads 发布到 Core orchestration 设置的选项。请单独审阅并确认该预览；拒绝发布不会撤销 squad 的变更。看板的 **New member** 表单可在你审阅命令后，通过可用的 host 启动 agent。使用 `squad add` 加入现有成员不会启动它。

Ops 看板使用你配置的用户身份。`tmt ops squad me` 显示该身份；`tmt ops squad me ben` 设置的全局名称与 `tmt config set user.name ben --global` 相同。这与哪个 agent 担任 squad lead 无关。

<Mdx.h3 id="the-workspace">工作区</Mdx.h3>

**Agents** 在 squad／成员树状列表与所选对话上方，显示横跨整个宽度的 Usage 区域。选择 squad 可查看成员；选择成员可查看 **Talk**、**Measure** 与 **Checklist**。Common pool 收录未加入任何 Ops squad 的身份；其中的成员没有 squad 对话清单。**Digest** 单独显示消息批处理与用量。**Orchestration** 显示 Core 的计划及生效策略；请参阅 [Orchestration](/working/orchestration)。

<Code>{`
OPS / UI · Agents
Usage: observed totals and provider limits
Squads / members       │ Talk · Measure · Checklist
▾ product              │ builder
  reviewer             │ Request and reply history
  builder              │
Common pool            │ Message to builder
`}</Code>

<Caption>Agents 视图示意图。宽终端并排显示，较窄时上下堆叠或只显示聚焦窗格。</Caption>

看板在后台更新信息。缺少读数表示未知，不代表空闲或零。切换视图时，注意事项摘要仍会显示。

| 默认按键        | 工作区中的操作                                            |
| --------------- | --------------------------------------------------------- |
| `1` / `2` / `3` | Agents / Digest / Orchestration；编辑器未处理该按键时生效 |
| `T` / `M` / `C` | Talk / Measure / 所选成员的 Checklist                     |
| Enter           | 聚焦所选对话的输入框                                      |
| Tab / Shift+Tab | 移动窗格焦点；活动编辑器或对话框会优先处理自己的按键      |
| `e`             | 编辑所选成员或 squad                                      |
| `l`             | 为成员选择私有看板标签                                    |
| `,` / `?`       | 设置 / 当前生效的操作说明                                 |
| Ctrl+R          | 刷新                                                      |

查看页脚和 `?`，了解所选目标可用的按键。你配置的按键绑定优先。点击窗格可聚焦；当前操作控件标有 `▸`。

<Mdx.h3 id="talk-without-losing-your-place">对话不中断工作位置</Mdx.h3>

在输入框按 Enter 发送消息。Alt+Enter 或 Ctrl+J 插入换行；终端支持增强按键回报时，也可用 Shift+Enter。Esc 离开编辑器并保留草稿。切换视图不会丢失草稿，但重启看板会清除草稿。

阅读较早的输出会暂停自动跟随。**Jump to latest** 或 End 可回到最新消息。回复与窗格输出会分别标注。若送达状态不确定，请先检查请求再决定是否重发。

<Mdx.h3 id="checklists-belong-to-a-room">清单属于 room</Mdx.h3>

每个 room 都有清单，每位成员也可以在其中拥有独立的对话清单。重新命名后，清单仍属于原来的 room 和成员。

选择成员并按 **C** 打开 Checklist。在聊天编辑器中，**Ctrl+L** 打开该清单并保留草稿和光标位置；Esc 返回编辑器。链接和待办事项会显示作者及经过时间。已归档的项目会隐藏。

<Code>{`
Checklist · builder
[ ] Verify the final head       you · 2m
    https://example.org/review
[x] Record the build result     builder · 5m
`}</Code>

<Caption>清单示例。勾选项目会完成该待办事项；等待回复的请求仍需单独答复。</Caption>

Agent 可用三个简短命令维护自己的对话清单。同时加入多个 squad 时，请加上 `--room` 并指定精确的 room UUID。请使用自己运行 `add` 或 `ls` 得到的短项目 ID，不要使用下方的示例 ID。

<Cmd>{`
$ tmt ops squad checklist add "Verify the final head"
$ tmt ops squad checklist ls --json
$ tmt ops squad checklist done 3f2a
`}</Cmd>

要查看特定 room 或成员的清单，请明确指定标识符。以下只读示例使用占位 room UUID；请换成你打算读取的 room。

<Cmd>{`
$ tmt ops squad checklist ls --room 44444444-4444-4444-8444-444444444444 --json
$ tmt ops squad checklist ls --room 44444444-4444-4444-8444-444444444444 --member builder --json
`}</Cmd>

| 身份                 | 允许的清单变更                                           |
| -------------------- | -------------------------------------------------------- |
| 当前 room 成员       | 创建未分配项目；编辑内容；完成或重新打开未归档的项目     |
| 用户或当前 room lead | 上述操作，加上分配／取消分配、归档／还原、删除与重新排序 |

更多清单操作请运行 `tmt ops squad checklist --help` 查看。

<Mdx.h3 id="read-usage-as-observations">把用量视为观测结果</Mdx.h3>

在 Settings 选择 **Token window**，查看已完成请求的总量。输入加输出只会把缓存输入计算一次。请同时查看覆盖标记：缺少读数不代表零，token 总量也不等于费用。

Digest 的 **Est. ctx avoided** 是通过批处理省下多少上下文输入的估计，不是实测的计费 token、轮次或金额节省。它的范围与 Agents 的 token 时间窗独立。读取任何总量时，都要一起看覆盖范围。

<Mdx.h3 id="make-it-yours">按你的方式配置</Mdx.h3>

按 `,` 打开 Settings。**New member** 和 **Edit** 会让你在应用前查看准备执行的命令或变更。

<Cmd>{`
$ tmt ops ui --squad product --squad infra
$ tmt ops ui --view popup --popup
$ tmt ops ui --tab digest
$ tmt ops squad config show --squad product
`}</Cmd>

重复指定 `--squad` 可限制本次看板会话的范围，不会改写已保存的隐藏 squad 设置。命名的 `--view` 各自保留目的地、选中项、搜索与窗格布局。**Reset view** 清除此视图层，不会移除 squad 成员或其工作。原地重新加载会保留当前视图与位置。

<Mdx.h3 id="layout-rows-lines-and-panes">布局：行、显示行与窗格</Mdx.h3>

交互式 Agents 树状列表与对话有自己的布局。拖动可见分隔线可调整相邻窗格大小；双击可恢复默认值。小型终端会维持可用的最小尺寸，也可能只显示聚焦窗格。窗格比例属于命名视图。

自定义 rows、columns、sections 与 `[tabs.<name>]` 配置仍用于独立的命令行成员视图。它们不会添加交互式 shell 标签页，也不会重新排列 Agents 树状列表。可用 `tmt ops squad ls --tab <name> --json` 读取。[Ops skill](https://github.com/tmt-ninja/tmt/blob/main/extensions/tmt-ops/skills/tmt-ops/SKILL.md) 提供详细配置参考。

<Mdx.h3 id="colors-and-themes">颜色与主题</Mdx.h3>

看板主题与命令行颜色分别配置。在 Settings 选择 **Theme**，应用到所有看板或所选 squad。即使使用 `NO_COLOR`，文字、符号与焦点提示仍会传达含义；颜色本身不能证明工作中、受阻或等待状态。Basic driver 无法报告与 full driver 相同的活动／模型细节，看板会标注这项限制。

<Mdx.h3 id="jumping-between-members">切换到成员</Mdx.h3>

在看板对话与跳到 agent 终端是不同操作。请使用所选成员可用的跳转操作，或在你的 tmux client 执行下列命令。跳转会改变你看到的画面，不会改变收件人的工作；返回则回到该次 squad 跳转的起点。

<Cmd>{`
$ tmt ops squad jump builder --squad product
$ tmt ops squad back
`}</Cmd>

打开成员的 Session 信息，查看目标及准备执行的 resume 或 move 命令。

<Mdx.h3 id="skills-for-your-lead">给 lead 的 skill</Mdx.h3>

`tmt extension install ops --skills` 会随扩展发布 lead skill。请 lead 阅读它，并与你约定命名、派工、状态更新与审查方式。

<Mdx.h3 id="where-state-lives">状态存放在哪里</Mdx.h3>

使用 `tmt notes path` 查找成员的笔记本。将持续需要的工作上下文保存在其中，并用 task、state 和 pending 字段概括当前情况。
