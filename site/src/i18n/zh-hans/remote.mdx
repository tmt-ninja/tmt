Remote 提供本机浏览器入口，并通过你自己的 Firebase 项目共享。先在本机读取 agent、使用已安装的浏览器应用。要连接另一台机器，请部署 Firestore、邀请其所有者，并分别选择两个方向的发送权限。

<Mdx.h3 id="start-the-local-door">启动本机入口</Mdx.h3>

<Cmd>{`
$ tmt extension install remote
$ tmt remote serve
$ tmt remote status --json
`}</Cmd>

普通的 `serve` 命令在后台启动，并显示本机浏览器地址。`--foreground` 让它保持连接到当前终端。它监听 IPv4 回环地址，不是公开网站。运行 `tmt remote stop` 可停止服务并保留已配对的设备。

<Mdx.h3 id="connect-your-browser">连接浏览器</Mdx.h3>

请亲自打开正在运行的入口：

<Cmd>{`$ tmt remote open /remote/`}</Cmd>

新浏览器以只读权限连接。手动配对时，运行 `tmt remote pair`，打开链接或输入代码，对照四个单词后确认。配对默认只读、无到期时间。所有者可用 `--talk` 允许发送；`--agents` 限定 agent UUID，`--hold` 要求本机批准。配对和权限变更由机器所有者操作。

<Mdx.h3 id="connect-two-machines">连接两台机器</Mdx.h3>

先在部署所有者的机器上完成 [Firestore 设置](/#review-and-deploy)。两台机器都保持运行 `tmt remote serve`。所有者邀请协作者：

<Cmd>{`
$ tmt remote invite --remote <owned-remote>
$ tmt remote join <code>    # on the collaborator's machine
`}</Cmd>

请私下共享一次性代码，并通过可信的对话渠道核对四个单词。双方分别决定是否允许对方向自己的 agent 发送消息；两个选项默认都不允许。请保留命令显示的 remote 引用。

<Mdx.h3 id="send-and-read-a-reply">发送并读取回复</Mdx.h3>

使用已有的本机 identity 作为发送者，并使用配对获得的对端引用：

<Cmd>{`
$ tmt talk --identity coordinator --remote <peer-reference> reviewer "Review the patch."
$ tmt result <request-id> --json
`}</Cmd>

远端接收者照常用绑定 receipt 的 `tmt reply` 回答。当两端的本机入口都在运行时，加密的最终回复会返回发起机器。回复保存到该机器后，就能离线读取。送达结果不确定时，不要重复发送同一请求；保留请求 ID 并检查原请求的结果。

<Mdx.h3 id="manage-access">管理访问</Mdx.h3>

<Cmd>{`
$ tmt remote members
$ tmt remote members sending <member-id> on
`}</Cmd>

每个接收方的所有者负责控制发送权限、允许的 agent 和待批准请求。待批准的发送会等待本机批准；`tmt remote approve` 用来审阅一项内容已固定的操作。查看机器或撤销访问的方式请见 `tmt remote members --help`。用 `tmt remote rm` 移除记住的 remote 引用，不等于撤销成员权限。

Remote 不运营中央 TMT 服务。Firestore 共享使用你部署的项目；停止本机入口只会推迟送达，不会取消已保存的请求。浏览器配对、云端登录和发送权限是不同的步骤。
