<Lede>
  Squad は lead とメンバーが仕事を調整する場所です。Ops が会話、作業、チェックリストを表示し、lead
  が担当を決めます。
</Lede>

<Mdx.h3 id="start-a-squad">Squad を作る</Mdx.h3>

Squad は `squad-<name>` という名前の room です。すでに動かしている agent を追加し、lead を選んでから board を開きます。Lead の指定と、メンバーを説明する role は別です。Squad からメンバーを外しても、その agent は停止しません。

<Cmd>{`
$ tmt extension install ops --skills
$ tmt ops squad init product
$ tmt ops squad add builder reviewer --squad product
$ tmt ops squad lead reviewer --squad product
$ tmt ops ui
`}</Cmd>

Lead を選ぶと、現在の Ops leads を Core の orchestration 設定に公開する選択肢も表示されます。この別のプレビューを確認して承認してください。公開を断っても squad の変更は残ります。Board の **New member** フォームでは、コマンドを確認した後、利用可能な host を通じて agent を起動できます。`squad add` で既存メンバーを追加しても起動はしません。

Ops の board は設定済みのユーザー identity を使います。`tmt ops squad me` で確認できます。`tmt ops squad me ben` は `tmt config set user.name ben --global` と同じグローバル名を設定します。どの agent が squad の lead を務めるかとは独立しています。

<Mdx.h3 id="the-workspace">ワークスペース</Mdx.h3>

**Agents** は squad／メンバーツリーと選択中の会話の上に、全幅の Usage 領域を表示します。Squad を選ぶとメンバーを、メンバーを選ぶと **Talk**、**Measure**、**Checklist** を確認できます。Common pool には、どの Ops squad にも属していない identity が入ります。そのメンバーには squad の会話チェックリストがありません。**Digest** はメッセージのまとめ送りと使用量を別のビューで表示します。**Orchestration** は Core のプランと有効なポリシーを表示します。[Orchestration](/working/orchestration) を参照してください。

<Code>{`
OPS / UI · Agents
Usage: observed totals and provider limits
Squads / members       │ Talk · Measure · Checklist
▾ product              │ builder
  reviewer             │ Request and reply history
  builder              │
Common pool            │ Message to builder
`}</Code>

<Caption>
  ソースに基づく Agents の模式図です。ライブの board
  や正確な端末キャプチャではありません。名前や値は例です。
  広い端末では横に並び、狭い端末では縦に並ぶか、フォーカス中のペインだけを表示します。本ページの例はメッセージ送信やチェックリスト変更を行いません。
</Caption>

Board は情報をバックグラウンドで取得します。観測がない状態は不明であり、アイドルやゼロではありません。ビューを切り替えても、shell の注意事項の概要は全体を対象とします。手動の task／state フィールド、チェックリストの未完了項目、返信待ちのリクエストは、それぞれ独立した情報です。

| 既定のキー      | ワークスペースでの操作                                                          |
| --------------- | ------------------------------------------------------------------------------- |
| `1` / `2` / `3` | Agents / Digest / Orchestration。エディターがそのキーを処理していない場合に有効 |
| `T` / `M` / `C` | Talk / Measure / 選択中のメンバーの Checklist                                   |
| Enter           | 選択中の会話の入力欄にフォーカス                                                |
| Tab / Shift+Tab | ペインのフォーカスを移動。使用中のエディターやダイアログは自分のキーを先に処理  |
| `e`             | 選択中のメンバーや squad を編集                                                 |
| `l`             | メンバーの個人用 board ラベルを選択                                             |
| `,` / `?`       | 設定 / 有効な操作のヘルプ                                                       |
| Ctrl+R          | 更新                                                                            |

設定したキーバインドが優先されます。選択対象で使える操作はフッターと `?` で確認してください。クリックはペインにフォーカスするだけで送信しません。ペインをスクロールしても宛先は変わりません。フォーカス中のコントロールの罫線は明るくなり、`▸` が付きます。選択状態とキーボードフォーカスは別です。

<Mdx.h3 id="talk-without-losing-your-place">作業位置を保ちながら会話する</Mdx.h3>

入力欄では Enter で送信します。Alt+Enter または Ctrl+J で改行します。端末が拡張キーを報告する場合は Shift+Enter も使えます。Esc は下書きを残してエディターを離れます。ブラケット付き貼り付けでは送信されません。ビューや所属が変わっても下書きは agent の UUID に紐づきますが、通常の board 再起動では保持されません。

古い出力を読むと自動追従が止まります。**Jump to latest** または End で最新メッセージに戻ります。関連づけられた返信と観測したペイン出力は別々に表示されます。ペインの文字だけではリクエストの完了になりません。リクエストが受理されると、配信が不確実でも送信済みの下書きは消えます。再送する前に、そのリクエストを確認してください。リクエストを保存せずに拒否された場合は、下書きが残ります。

<Mdx.h3 id="checklists-belong-to-a-room">チェックリストは room に属する</Mdx.h3>

Room は手動で記入する独自のチェックリストを持ちます。各メンバーも、その room に個別の会話チェックリストを持てます。Room とメンバーの UUID によって、名前が変わってもリストは維持されます。同名の別 identity には引き継がれません。読み取りだけではリストを作りません。最初の追加が許可された時点で作成します。

メンバーを選んで **C** を押すと Checklist が開きます。チャットエディターでは **Ctrl+L** で選択中のメンバーのリストを開き、下書きとカーソル位置を保持します。Esc でエディターに戻ります。リンクと todo は一緒に表示され、分かる場合は作成者と経過時間が付きます。参照リンクのある項目も未完了／完了を切り替えられます。アーカイブ済み項目は通常のリストと件数から除かれます。

<Code>{`
Checklist · builder
[ ] Verify the final head       you · 2m
    https://example.org/review
[x] Record the build result     builder · 5m
`}</Code>

<Caption>
  チェックリストの状態例です。リンクは参照であり、タスクの依頼ではありません。チェックを付けてもリクエストへの返信やメンバーの
  pending 状態の解除にはなりません。
</Caption>

Agent は短い 3 つのコマンドで自分の会話リストを管理できます。複数の squad に属する場合は、`--room` に正確な room UUID を指定してください。下の例の ID ではなく、自分の `add` や `ls` が返した短い項目 ID を使います。

<Cmd>{`
$ tmt ops squad checklist add "Verify the final head"
$ tmt ops squad checklist ls --json
$ tmt ops squad checklist done 3f2a
`}</Cmd>

特定の room やメンバーのリストを読むには、識別子を明示します。次の読み取り専用の例では仮の room UUID を使っています。読む対象の room に置き換えてください。

<Cmd>{`
$ tmt ops squad checklist ls --room 44444444-4444-4444-8444-444444444444 --json
$ tmt ops squad checklist ls --room 44444444-4444-4444-8444-444444444444 --member builder --json
`}</Cmd>

| 実行者                         | 許可されるチェックリストの変更                                 |
| ------------------------------ | -------------------------------------------------------------- |
| 現在の room メンバー           | 未割り当て項目の作成、内容の編集、未アーカイブ項目の完了・再開 |
| ユーザーまたは現在の room lead | 上記に加え、割り当て・解除、アーカイブ・復元、削除、並べ替え   |

作成時に自分へ割り当てる場合も管理権限が必要です。担当者は同じ room の有効なメンバーでなければなりません。割り当ては責任の記録であり、メッセージ送信、agent の起動、task／pending フィールドの更新はしません。Room を離れた担当者は、管理者が変更するまで利用不可の担当者として残ります。

自動化向けの `create`、`edit`、`assign`、`complete` などの明示的な動詞は、正確な UUID と項目／リストのリビジョンを使います。入力は `tmt ops squad checklist --help` と各動詞のヘルプで確認できます。リビジョンが古い場合や権限が変わった場合は変更を拒否します。現在のリストを読み直し、確認したうえで新たに明示的な選択をしてください。**Outcome unknown** は再実行の許可ではありません。Board も同じ権限とリビジョンの検査を使います。

アーカイブは内容、完了状態、位置を保持します。復元は完了状態を変えずに再表示します。削除は記入内容を除き、最小限の削除記録だけを残します。項目を完了しても、リクエスト、受信箱の注意事項、手動の状態、pending フラグは変わりません。待機中のリクエストには別に返信してください。

<Mdx.h3 id="read-usage-as-observations">使用量を観測値として読む</Mdx.h3>

Token の時間窓は完了したリクエストの合計であり、毎秒の token 数や予測ではありません。入力と出力の合計ではキャッシュ入力を一度だけ数えます。Settings の **Token window** で選択します。`0` は観測されたゼロです。不完全な範囲や取得不能な値には別の印が付きます。カウンターのないメンバーはコストゼロではなく、異なるプロバイダーの token 合計は比較可能な価格でもありません。

数字は最大 600 ms かけて新しい合計へ変化する場合があります。これは表示だけの変化です。最終的な合計、比率、観測範囲は観測値に基づきます。最初の読み取り、取得不能な値、データの所有者や時間窓の変更、動きを減らす設定では、最終値をすぐに表示します。

Digest の **Est. ctx avoided** は、まとめ送りで省いたコンテキスト入力の推定値です。実測した課金 token、ターン、金額の節約ではありません。その範囲は Agents の token 時間窓とは独立しています。どの合計でも観測範囲と一緒に読んでください。

<Mdx.h3 id="make-it-yours">自分に合わせる</Mdx.h3>

`,` で設定を開き、そこに表示される有効な操作を使います。**New member** と **Edit** は、適用前にコマンドや変更案を表示します。失敗した場合、一部の手順だけが適用され、残りが未実行のことがあります。ダイアログが閉じたことを成功とみなさず、結果を読んでください。本ページの例を読むだけでユーザーの設定が変わることはありません。

<Cmd>{`
$ tmt ops ui --squad product --squad infra
$ tmt ops ui --view popup --popup
$ tmt ops ui --tab digest
$ tmt ops squad config show --squad product
`}</Cmd>

`--squad` を繰り返すと、保存済みの非表示 squad 設定を変更せずに、この board セッションの対象を限定できます。名前付きの `--view` は、移動先、選択、検索、ペイン配置を個別に保持します。**Reset view** はそのビューの層を消しますが、squad のメンバーや仕事は削除しません。その場での再読み込みは現在のビューと位置を保持します。

<Mdx.h3 id="layout-rows-lines-and-panes">レイアウト：行、表示行、ペイン</Mdx.h3>

対話型の Agents ツリーと会話には独自のレイアウトがあります。表示中の区切り線をドラッグすると隣接するペインのサイズが変わり、ダブルクリックで既定値に戻ります。小さい端末では使える最小サイズを保ち、フォーカス中のペインだけを表示する場合があります。ペイン比率は名前付きビューに属します。

独自の rows、columns、sections、`[tabs.<name>]` 設定は、引き続き独立したコマンドラインのメンバー表示を定義します。対話型 shell のタブを増やしたり、Agents ツリーを並べ替えたりはしません。`tmt ops squad ls --tab <name> --json` で読めます。詳細な設定は [Ops skill](https://github.com/tmt-ninja/tmt/blob/main/extensions/tmt-ops/skills/tmt-ops/SKILL.md) を参照してください。

<Mdx.h3 id="colors-and-themes">色とテーマ</Mdx.h3>

Board のテーマはコマンドラインの色とは別です。Settings の **Theme** で、すべての board または選択中の squad を対象にします。`NO_COLOR` でも、文字、記号、フォーカスの印が意味を伝えます。色だけで作業中、ブロック中、待機中とは判断しません。Basic driver は full driver と同じ活動／モデル情報を報告できず、board はその制約を表示します。

<Mdx.h3 id="jumping-between-members">メンバー間を移動する</Mdx.h3>

Board で話す操作と、agent の端末へ移動する操作は別です。選択中のメンバーで使える移動操作か、tmux client 内で次のコマンドを使います。移動で変わるのは自分の表示であり、宛先の作業ではありません。戻る操作は、その squad の移動を始めた場所へ戻ります。

<Cmd>{`
$ tmt ops squad jump builder --squad product
$ tmt ops squad back
`}</Cmd>

Board ではメンバーの Session 情報も表示できます。確認する前に、正確な対象と提示された resume／move コマンドを読んでください。実行状態が欠けている、または未観測であることは、別の agent を安全に起動できる証拠ではありません。

<Mdx.h3 id="skills-for-your-lead">Lead のための skill</Mdx.h3>

`tmt extension install ops --skills` は拡張とともに lead skill を公開します。Lead に読んでもらい、命名、仕事の依頼、状態更新、レビューの進め方を合意してください。Skill はコマンドの動作を説明するもので、追加の agent 起動やワークフロー変更を許可するものではありません。

<Mdx.h3 id="where-state-lives">状態の保存先</Mdx.h3>

Core は identity、room の所属、リクエスト、返信を管理します。Ops はチェックリストと board の設定を管理し、ビューのキャッシュは破棄できます。メンバーのノートは `tmt notes path` が示す場所にあり、行の `note` フィールドにある別のコピーではありません。継続して必要な作業の文脈はノートに残し、task、state、pending フィールドには現在の概要を記録します。
