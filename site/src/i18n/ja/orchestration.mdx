<Lede>
  チームへの割り込み頻度を一日中同じにする必要はありません。Orchestration は時間帯に合わせて、各
  agent の受信、送信、定期実行の方針を設定します。
</Lede>

<KeyList>
  <li>
    <strong>プラン</strong>は、ローカル暦の時間枠で選択した agent に方針を適用します。
  </li>
  <li>
    <strong>個人の focus</strong>は、一時的にすべてのプランより優先されます。
  </li>
  <li>
    <strong>ジョブ</strong>は、時計と現在の方針が許可したときに定期リクエストを送ります。
  </li>
</KeyList>

CLI、Ops、メッセージやジョブの判断は、同じ Core の解決処理を使います。実行中の agent の仕事を止めるものではありません。プランがなくても Base が適用されます。状態は awake、受信は設定済みの Digest 方式、送信先は誰でも、定期ジョブは実行、talk 数は無制限です。一致する優先度の高いプランが、指定した項目を上書きします。プラン内のメンバー別設定は、そのプランの既定値を上書きできます。

<Mdx.h3 id="read-the-day">一日の状態を読む</Mdx.h3>

<Cmd>{`
$ tmt orch
$ tmt orch --range 7d --member worker --json
$ tmt orch --at "2026-11-05 09:00" --plan Quiet
$ tmt orch why req_11111111-1111-4111-8111-111111111111
`}</Cmd>

タイムラインにはローカル暦の時間枠と有効な方針が表示されます。範囲は `1d`、`7d`、`30d` から選びます。`--at` はローカル日時か、オフセット付きの RFC3339 時刻を受け取ります。曖昧な、または存在しないローカル時刻には明示的なオフセットが必要です。`--plan` は表示するタイムラインを絞るだけで、メンバーの方針を決める他のプランは除外しません。`why` は保存された判断を読みます。記録がないことは、何も起きなかった証拠にはなりません。過去の概要は、現在の設定をその時点に当てはめた結果であり、昔の設定を復元したものではありません。

<Mdx.h3 id="plans-and-focus">プランと focus</Mdx.h3>

<Cmd>{`
$ tmt orch plan ls
$ tmt orch plan show Quiet
$ tmt orch preview --file plan.json
$ tmt orch plan add --file plan.json
$ tmt orch plan set Quiet --file plan.json
$ tmt orch focus worker-1 2h
$ tmt orch focus worker-1 off
`}</Cmd>

プランは全 agent、保存済み identity、名前パターンのいずれかを対象にし、予定と方針項目を定義します。候補は保存せずにプレビューできます。追加、変更、削除も、同意を求める前に影響を表示します。非対話で変更を適用するには `--yes` が必要で、付けなければプレビューを返します。古くなったプレビューは拒否されるので、現在の状態を読み直して再度プレビューしてください。`tmt orch plan rm Quiet` も同じ確認を経てプランを削除します。

状態には、プランで上書きできる既定値があります。**awake** は直接受信し、ジョブを実行します。**low** は30分単位でまとめて受信し、ジョブを実行します。**focus** は緊急メッセージを受信し、ジョブを保留します。**sleep** は緊急を含む自動配信とジョブを保留します。送信は別の項目です。個人の focus はすべてのプランに優先して緊急のみの受信と定期ジョブの保留を設定し、送信は変更しません。Digest 全体をオフにすると直接受信になり、人からのメッセージには別の受け入れ規則が適用されます。

<Mdx.h3 id="receiving-and-wake-up">受信と通知</Mdx.h3>

保留されたリクエストは inbox に残ります。制限が解除されると、Digest は準備のできた agent に `you have N messages, K urgent: tmt inbox` のような1行を送り、agent が自分の inbox を読みます。sleep から focus への変更では、通常のメッセージを保留したまま緊急メッセージだけを解放できます。通知間隔は最低1秒で、オフライン、処理中、承認待ちの agent は引き続き待機します。通知自体はリクエストへの回答ではありません。継続して保留と解放を行うには、Digest をインストールし、その tick を動かす必要があります。

<Callout title="プランは割り込みではありません。">
  プランを保存しても実行中の仕事は止まらず、処理中の agent
  が受信可能になるわけでもありません。配信は引き続き受信者の準備状態と承認規則に従います。
</Callout>

<Mdx.h3 id="sending-and-talk-limits">送信と talk の上限</Mdx.h3>

送信側の方針では、送信先を誰でも、lead のみ、または agent 間の新規リクエストを一時停止にできます。制限された経路は、リクエストの保存前に拒否されます。`--urgent` でも回避できません。人、返信、結果通知にはそれぞれ別の処理が適用されます。

<Cmd>{`
$ tmt orch routes --member worker
$ tmt orch leads set team-lead
$ tmt orch route allow worker-1 reviewer --until 1h
$ tmt orch talks
$ tmt orch talks resume worker-1 reviewer
`}</Cmd>

lead の一覧は明示的に設定し、Ops から squad の lead を反映できます。経路の許可は方向を持つ1組が対象で、有効期限があります。talk の上限は解除しません。既定では無制限です。設定された組の上限に達すると、新規リクエストは破棄されず、保存されて人の判断を待ちます。resume はその組を通常の配信に戻します。まず影響のプレビューを確認してください。

<Mdx.h3 id="routine-jobs-and-the-clock">定期ジョブと時計</Mdx.h3>

<Cmd>{`
$ tmt orch job ls
$ tmt orch job show j1
$ tmt orch job add --file job.json
$ tmt orch job pause j1
$ tmt orch job resume j1
$ tmt tick status
$ tmt tick run
$ tmt tick timer preview
`}</Cmd>

ジョブは agent に属し、予定とメッセージを持ちます。`tmt orch job` で確認、追加、編集、一時停止、再開、担当変更、削除ができます。変更は同意の前にプレビューされます。手動の一時停止は明示的に再開するまで続きます。定期実行方針による保留では、確認済みの実行枠を1つ保持して後で解放でき、手動の一時停止とは別に扱います。リクエストの受け付けは、配信や完了を意味しません。

`tmt tick` は現在の1分間のジョブ、Digest、ワークスペース取得を実行します。`tmt tick run` は中断されるまでフォアグラウンドで時計を動かします。Ops ボードも時計を担当できます。lease を持つ時計は1つだけで、時計が動いていなかった時間の処理を後からまとめて実行することはありません。タイマーは自動ではインストールされません。任意のユーザー別タイマーが必要なら、まず `tmt tick timer preview` を確認してください。インストールと削除には同意が必要です。このタイマーは毎分1回の有限な tick を実行し、別の Ops アイドル通知 worker は起動しません。

<Mdx.h3 id="in-ops">Ops で使う</Mdx.h3>

端末の Ops ボードの **Orchestration** タブで時間枠、プラン、メンバーの方針、経路を確認します。変更は確認用のプレビューを表示します。CLI はスクリプト向けにテキストと `--json` も提供します。
