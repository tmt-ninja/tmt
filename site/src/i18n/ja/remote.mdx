Remote はローカルのブラウザー接続口と、自分の Firebase プロジェクトを使った共有を提供します。まずローカルで agent を読み取り、インストール済みのブラウザーアプリを使えます。別のマシンにつなぐには Firestore をデプロイし、その所有者を招待して、双方の送信権限を選びます。

<Mdx.h3 id="start-the-local-door">ローカルの接続口を起動する</Mdx.h3>

<Cmd>{`
$ tmt extension install remote
$ tmt remote serve
$ tmt remote status --json
`}</Cmd>

通常の `serve` はバックグラウンドで起動し、ローカルのブラウザーアドレスを表示します。`--foreground` では端末に接続したまま動作します。IPv4 ループバックで待ち受けるため、公開 Web サイトではありません。`tmt remote stop` はペアリング済みデバイスを残したまま停止します。

<Mdx.h3 id="connect-your-browser">ブラウザーを接続する</Mdx.h3>

起動中の接続口を自分で開きます。

<Cmd>{`$ tmt remote open /remote/`}</Cmd>

新しいブラウザーは読み取り専用で接続します。手動でペアリングするには `tmt remote pair` を実行し、リンクを開くかコードを入力して、4つの単語を照合して確認します。既定では有効期限のない読み取り専用です。送信を許可するには所有者が `--talk` を使えます。`--agents` は対象 agent の UUID を絞り、`--hold` はローカルでの承認を必須にします。ペアリングと権限変更はマシンの所有者が行います。

<Mdx.h3 id="connect-two-machines">2台のマシンを接続する</Mdx.h3>

まずデプロイ担当者のマシンで [Firestore のセットアップ](/#review-and-deploy)を済ませます。両方のマシンで `tmt remote serve` を動かしておき、所有者が共同作業者を招待します。

<Cmd>{`
$ tmt remote invite --remote <owned-remote>
$ tmt remote join <code>    # on the collaborator's machine
`}</Cmd>

1回限りのコードは非公開で共有します。信頼できる会話手段で4つの単語を照合してください。双方が、自分の agent への送信を相手に許可するか選びます。どちらも既定では許可しません。コマンドが表示した remote 参照を控えておきます。

<Mdx.h3 id="send-and-read-a-reply">送信して返事を読む</Mdx.h3>

送信元には既存のローカル identity、宛先にはペアリングで得た相手の参照を使います。

<Cmd>{`
$ tmt talk --identity coordinator --remote <peer-reference> reviewer "Review the patch."
$ tmt result <request-id> --json
`}</Cmd>

リモート側の受信者は、通常どおり receipt に紐づく `tmt reply` で回答します。両方のローカル接続口が動いていれば、暗号化された最終回答が送信元のマシンに戻ります。そこに保存された後はオフラインでも結果を読めます。配信が不確かでも、同じリクエストを送り直さず、元のリクエスト ID を使って結果を確認してください。

<Mdx.h3 id="manage-access">アクセスを管理する</Mdx.h3>

<Cmd>{`
$ tmt remote members
$ tmt remote members sending <member-id> on
`}</Cmd>

受信側の所有者が、送信権限、許可する agent、保留するリクエストを管理します。保留された送信はローカルでの承認を待ち、`tmt remote approve` では内容を固定した1つの操作を確認します。マシンの確認やアクセスの取り消しは `tmt remote members --help` を参照してください。`tmt remote rm` で保存済み remote 参照を削除しても、メンバーの権限を取り消したことにはなりません。

Remote は TMT の中央サービスを運営しません。Firestore 共有は自分でデプロイしたプロジェクトを使います。ローカルの接続口を止めると配信は延期されますが、保存されたリクエストは取り消されません。ブラウザーのペアリング、クラウドへのサインイン、送信権限は別々の手順です。
