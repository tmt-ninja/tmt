<Mdx.h3 id="connect-it">接続する</Mdx.h3>

<Cmd>{`
$ tmt setup codex           # shows the exact config change, then asks
$ tmt run builder codex     # start Codex as "builder"
$ tmt resume builder        # reopen builder's own thread
`}</Cmd>

setup は tmt 用の lifecycle hook を Codex に追加します。初回は Codex が新しい hook を信頼するか尋ねます。これは正常な動作です。`tmt setup codex --remove` で取り除けます。

<Mdx.h3 id="message-delivery">メッセージの配信</Mdx.h3>

`tmt run <name> codex` は既定で通常の貼り付けを使います。実験的 channel 設定を有効にして `--channel` を指定すると、channel を使えます。その後の `tmt resume <name>` は記憶した channel の選択を引き継ぎます。channel では `talk` が専用の app-server を通して入力をキューに入れるため、ペインに貼り付けず、ユーザーの入力も中断しません。channel の各セッションには、tmt が管理する追加の app-server プロセスと supervisor が1つずつ付きます。Ctrl-C を含め、フォアグラウンドの処理が終了したときに tmt が片付けます。

[run と resume のオプション](/working#tmt-run)で、通常の貼り付けを選ぶか、channel を必須にするか指定できます。

<Cmd>{`
$ tmt run --channel builder codex    # opt into the channel
$ tmt resume --channel builder       # require the channel for this exact thread
`}</Cmd>

使っている Codex のバージョンが未検証の場合や、起動前に channel を安全に準備できない場合、`--channel` は失敗します。ペインがすでに channel に接続している可能性があれば、tmt は貼り付けへの切り替えを拒否します。登録後に channel の準備が整わない場合や配信できない場合もエラーのままとし、代わりにペインへ貼り付けることはありません。

Codex が起動フォルダーを信頼するか尋ねることがあります。その TUI で自分で回答してください。tmt は回答や信頼設定の変更をしません。キューに受け付けられた入力も、接続が完了するまで待つ場合があります。通常の `codex` の実行は変わりません。channel 登録のために、tmt が Codex のグローバル設定、認証、hook を変更することもありません。

<Mdx.h3 id="codex-s-sandbox">Codex の sandbox</Mdx.h3>

通常の Codex workspace-write セッションでは、tmt のデータディレクトリにアクセスできない場合があります。書き込みが拒否されると、tmt はパス付きの `STORAGE_NOT_WRITABLE` を返します。`tmt run <name> codex` は、グローバル設定を編集せず、その起動だけにデータディレクトリへのアクセスを追加します。既存のセッションでは Codex 自身の権限確認でディレクトリを許可するか、コマンドの権限を昇格してください。agent はユーザーの了承なしに設定を変更すべきではありません。

<Mdx.h3 id="usage-counters">使用量カウンター</Mdx.h3>

新規インストールでは、`tmt setup codex` は Codex のコンテキストサイズと完了したリクエストの token の記録を既定で有効にします。`--no-usage` は記録を無効にして選択を保存し、`--usage` は有効にします。ターン終了 hook が値を記録します。フィールドは[使用量カウンター](/drivers#usage-counters)を参照してください。Codex はコンテキストウィンドウを報告するため、`windowTokens` が入ります。カウンターは provider 自身の累計値に従います。最初の読み取りを基準に、その後のターンで加算します。
