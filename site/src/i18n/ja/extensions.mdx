PATH 上の `tmt-<name>` というプログラムは、`tmt <name>` として呼び出せます。gcloud にコンポーネントがコマンドを追加するのと同じ仕組みです。組み込みコマンドが常に優先されるので、拡張機能が `talk` や `run` を置き換えることはありません。拡張機能は、ほかのプログラムと同じくコマンド、JSON 出力、hook を通して tmt を使います。

<Cmd>{`
$ tmt ops ui           # runs tmt-ops ui
$ tmt help             # lists extensions it found
$ tmt ops sq <Tab>     # completion comes from the extension
`}</Cmd>

<Mdx.h3 id="install-update-and-remove">インストール、更新、削除</Mdx.h3>

以下の拡張機能は同じ方法でインストールします。それぞれが独自のバージョンを持ち、別々の予定で更新されます。削除するとコマンドと skill は消えますが、データは残ります。

<Cmd>{`
$ tmt extension install ops       # asks before changing anything
$ tmt extension ls                # what's installed and its version; --check looks for updates
$ tmt upgrade                     # CLI, skills and installed official extensions
$ tmt extension upgrade ops       # just Ops
$ tmt extension rm ops            # your data stays
`}</Cmd>

`tmt upgrade` はインストール済みの公式拡張機能も、それぞれの channel と固定バージョンに従って更新し、まとめて一度確認します。`--yes` で確認を省略できます。未インストールの公式拡張機能も提案します。1つが失敗してもほかの更新は取り消しません。[更新計画を確認 →](/working/settings#update-tmt) `tmt extension upgrade <name> --unpin` でバージョンの固定を解除します。

通常のインストールでは agent 用の skill は追加しません。`--skills` を指定すると、承認するインストールに同梱の skill を含めます。skill だけを別に確認する質問はありません。自作する場合は[拡張機能を作る](/develop/extensions)を参照してください。PATH 上の `tmt-<name>` は `tmt extension` を使わなくても動きます。

<Mdx.h3 id="a-command-whose-extension-is-missing">拡張機能がないコマンド</Mdx.h3>

人が操作する端末で `tmt ops ui` など未インストールの公式コマンドを実行すると、tmt は対応する拡張機能を説明し、**Install it now [Y/n]** と質問します。この提案には同梱 skill も含まれます。承認するとインストールし、**Run it again:** と元のコマンドを表示します。コマンドを代わりに実行することはありません。断ると変更しません。help、JSON、パイプ、agent からの呼び出しでは対話的なインストールを提案せず、拡張機能がないことを示すエラーと明示的なインストールコマンドを返します。
